# Laporan QC penuh — 25 September 2026

**Keputusan: BELUM LULUS untuk release.** Aplikasi operasional dan WhatsApp terhubung, tetapi ada bug yang dapat menyebabkan pengiriman ganda, status sesi yang tidak sesuai adapter, dan kehilangan konten knowledge. Gate dependency, lint, versi host, dan visual juga belum lulus. Masalah aksi admin multi-tab telah diperbaiki pada 28 September 2026.

QC mencakup working tree saat ini (termasuk perubahan pengguna yang belum di-commit) serta stack Docker lokal. Tidak ada perbaikan produk/dependency atau redeploy pada sesi QC ini. Tingkat keparahan di bawah adalah penilaian dampak aplikasi; severity advisory berasal dari registry, bukan bukti bahwa setiap advisory dapat dieksploitasi pada deployment ini.

## Temuan prioritas tinggi

### QC-01 — Dependency memiliki advisory Critical/High; release gate gagal

**Bukti:** `corepack pnpm audit --audit-level=high` exit 1; output JSON disimpan. Next.js 16.3.0 terkena dua advisory Critical, dengan patched range >=16.3.3. Salah satunya khusus filesystem Windows, sehingga kondisi itu tidak cocok dengan container Linux sekarang. Advisory lainnya terkait optimisasi AVIF melalui sharp/libheif; keterjangkauan payload AVIF tidak dieksploitasi dalam QC ini.

Sharp 0.35.3 (lewat Next dan Baileys) juga tercatat High, patched >=0.35.4. High lain: nanoid, deepmerge-ts, mysql2, dan empat advisory fast-uri. Keberadaan dependensi transitif seperti mysql2 bukan bukti bahwa aplikasi PostgreSQL ini membuka jalur MySQL ke penyerang.

**Tindakan:** prioritaskan update terkontrol Next/sharp, kemudian dependensi transitif dan baseline policy/lockfile, build, serta regression test. Jangan menyebut semua advisory sebagai eksploit aktif.

Sumber primary/maintainer: [Next AVIF](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4), [Next Windows](https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36), [sharp](https://github.com/lovell/sharp/security/advisories/GHSA-rgj7-g3m4-5g8c). Hasil metadata registry untuk seluruh temuan ada pada JSON terlampir.

### QC-02 — Worker lama dapat mengirim outbox yang sudah dikirim worker lain

**High; direproduksi terisolasi.** [outbox.ts:168](../../apps/worker/src/outbox.ts#L168) mengubah status menjadi sending menggunakan id saja. Tidak ada pemeriksaan kepemilikan lease, deliveryAttemptId, maupun kedaluwarsa lease sebelum provider.send. Update hasil pada baris 195 juga tidak dibatasi pemilik attempt.

**Repro:** worker A mendapat lease, tertahan saat membaca state WhatsApp; waktu maju 31 detik; recovery mengembalikan job menjadi retryable; worker B mengirim; A melanjutkan dan mengirim lagi. Output fixture: `providerSendCount=2`, kedua worker melaporkan delivered untuk outbox yang sama.

**Tindakan:** gunakan compare-and-set terhadap status, attempt/pemilik lease dan masa berlaku sebelum send maupun saat finalize; worker yang kehilangan lease harus berhenti. Uji bersamaan dengan recovery.

### QC-03 — Pesan masuk dapat hilang ketika API tidak dapat menerima event

**High; review jalur kode, tidak mengganggu API live untuk memaksa kegagalan.** [inbound.ts:11](../../apps/whatsapp/src/inbound.ts#L11) hanya melakukan satu HTTP request dengan timeout 5 detik. [adapter.ts:140](../../apps/whatsapp/src/adapter.ts#L140) menangkap kegagalan dan hanya menulis log. `ingestInbound` bahkan menyelesaikan entry recovery sebelum menunggu sink (baris 180). Tidak ada durable retry untuk kegagalan pengiriman HTTP ke API; recovery queue yang ada menangani payload pesan yang belum terdekripsi/absen.

**Dampak:** saat API restart/timeout/5xx, suatu pesan dapat tidak masuk inbox jika tidak ada event ulang dari upstream.

**Tindakan:** persist event sebelum forwarding, retry dengan backoff dan idempotency key yang sama, acknowledge setelah API menerima.

### QC-04 — Reset sesi melaporkan logout tanpa mengakhiri adapter

**High; direproduksi terisolasi.** [app.ts:802](../../apps/api/src/app.ts#L802) hanya mengganti state database ke logged_out. Berbeda dengan disconnect, route reset tidak memanggil controller adapter.

**Repro:** fixture adapter connected, POST reset valid → HTTP 200 dan state logged_out, tetapi `disconnectCalls=0`, `reconnectCalls=0`.

**Dampak:** database/UI dapat menyatakan logout sementara socket dan autentikasi adapter masih hidup. Endpoint reset ini ada walaupun bukan tombol utama halaman sesi sekarang.

**Tindakan:** tentukan kontrak reset dan implementasikan koordinasi adapter, auth storage, audit, serta state setelah operasi berhasil.

### QC-05 — Sumber yang diarsipkan masih bisa lolos pencarian semantic

**High bersyarat: hanya jalur embedding/semantic; review kode, bukan kejadian live yang ditemukan.** [knowledge-repository.ts:938](../../apps/api/src/knowledge-repository.ts#L938) memfilter status versi published, tetapi tidak status KnowledgeItem atau pointer publishedVersionId.

**Urutan:** item v1 published → edit membuat v2 draft tanpa mengarsipkan v1 (baris 598–637) → arsipkan item mengubah currentVersion v2 saja (baris 685–705). V1 masih published dan chunk pada active index tetap memenuhi query semantic. Jika sumber terakhir hilang, buildIndex mengembalikan NO_PUBLISHED_SOURCE tanpa mengganti index ([knowledge.ts:319](../../apps/worker/src/knowledge.ts#L319)).

**Tindakan:** join item/published pointer dan status pada query, serta invalidasi index/cache yang konsisten ketika archive. Saat QC ini, embedding tidak dikonfigurasi dan query read-only menemukan **0** vector published yang terkait item nonaktif. Jalur lexical/exact sudah memiliki filter tambahan.

### QC-06 — Kegagalan embedding melempar error, melewati fallback dan trace

**High bersyarat: jalur semantic; direproduksi terisolasi.** [knowledge-repository.ts:924](../../apps/api/src/knowledge-repository.ts#L924) melempar error embedQuery; [search:1059](../../apps/api/src/knowledge-repository.ts#L1059) dan answer:1233 tidak menangkapnya sebelum lexical/fallback.

**Repro:** adapter fake melempar PROVIDER_TIMEOUT → answer ikut throw, `lexicalCalls=0`, `traceWrites=0`.

**Tindakan:** klasifikasikan kegagalan retrieval, jalankan fallback lexical bila diizinkan, atau persist safe fallback/handoff. Saat ini live memakai lexical (embedding tidak dikonfigurasi), jadi kegagalan ini tidak dipicu pada konfigurasi live sekarang.

## Temuan prioritas sedang

### QC-07 — Tab admin saling membatalkan token CSRF

**Diperbaiki 28 September 2026.** Token CSRF sekarang diturunkan dengan HMAC dari secret aplikasi dan ID sesi, sehingga stabil untuk satu sesi tetapi tetap berbeda antar-sesi. GET `/me` tidak lagi merotasi hash CSRF.

Regression test membuka dua konteks tab melalui GET `/me`, memastikan keduanya menerima token yang sama, lalu membuktikan token tab pertama masih dapat melakukan POST logout setelah tab kedua aktif. Bukti verifikasi: integration auth **7/7**, security **18/18**, unit **150/150**, dan typecheck API lulus.

### QC-08 — Sesi aktif tetap habis setelah 30 menit jika tidak memanggil /me lagi

**Diperbaiki 28 September 2026.** UI sekarang menandai request yang terjadi dalam 30 detik setelah interaksi pengguna (pointer, keyboard, touch, atau click). Middleware autentikasi memperpanjang idle expiry untuk request bertanda, dibatasi maksimum satu write database per 5 menit.

Polling background tidak mengirim penanda aktivitas, sehingga tidak dapat mempertahankan sesi tanpa pengguna. Regression test membuktikan aktivitas pada menit 10, 20, 29, dan 31 tetap mendapat **200**, sedangkan request setelah batas absolut 8 jam mendapat **401**. API/web typecheck, integration auth **8/8**, dan unit activity-signal **2/2** lulus.

### QC-09 — Gambar QR lama tetap terlihat setelah kedaluwarsa dan setelah connected

**Diperbaiki 28 September 2026.** Endpoint QR sekarang mengirim `X-QR-Expires-At` dari expiry adapter. UI menjadwalkan pencabutan object URL pada waktu tersebut, mencari QR pengganti selama state masih `qr_required`, dan langsung membersihkan QR ketika state berubah—termasuk saat connected.

Browser regression probe dengan request adapter dimock menghasilkan `replacedAfterExpiry=true`, `visibleAfterConnected=false`, `qrRequests=2`, dan `adapterActions=0`. Integration auth **8/8**, API/web typecheck, serta lint dan format file perubahan lulus.

### QC-10 — Chunking dapat melewatkan teks dokumen/knowledge

**Diperbaiki 28 September 2026.** Posisi awal chunk berikutnya sekarang dihitung dari `end` aktual chunk sebelumnya dikurangi overlap, bukan dari langkah tetap yang mengabaikan pemotongan pada batas spasi. Perubahan diterapkan konsisten pada pipeline dokumen worker dan lexical knowledge API.

Fixture 1000 karakter A + spasi + 700 karakter B sekarang menghasilkan chunk `[1000, 901]`; token B sepanjang 700 karakter tercakup utuh pada kedua implementasi. Test target **46/46**, seluruh unit test **154/154**, API/worker typecheck, lint, dan format lulus.

### QC-11 — Ekstraktor menolak PDF teks dengan operator yang umum

**Diperbaiki 28 September 2026.** Ekstraksi PDF sekarang memakai Mozilla PDF.js, bukan regex content stream. Parser menangani pemetaan font/encoding, literal `Tj`, array `TJ`, hex string, dan stream Flate terkompresi. Pipeline worker diubah menjadi async.

Perlindungan tetap fail-closed: batas input 10 MiB, maksimum 2.000 halaman, maksimum 2 juta karakter, rendering font/image dan WASM dinonaktifkan, serta JavaScript/attachment ditolak. Regression test worker **11/11** dan seluruh unit test **159/159** lulus; worker typecheck/build, lint, format, diff check, serta license scan juga lulus. PDF scan tanpa text layer tetap tidak dianggap memiliki teks; OCR tidak ditambahkan dalam perbaikan ini.

### QC-12 — Klarifikasi lokasi tidak menerima jawaban singkat yang diminta bot

**Direproduksi.** [location-distance.ts:307](../../apps/api/src/location-distance.ts#L307) mengharuskan pertanyaan baru mengandung intent terdekat sebelum membaca konteks.

“Cabang terdekat?” → bot meminta kecamatan/kota → “Grogol, Jakarta Barat” menghasilkan handler null, geocodeCalls=0. “Cabang terdekat mana?” bahkan diparse sebagai originQuery=mana. Simpan konteks klarifikasi atau gunakan giliran assistant/intent sebelumnya, dan tolak kata tanya sebagai asal lokasi.

### QC-13 — Dashboard menyebut semua pesan keluar sebagai “terkirim”

**Dikonfirmasi live dan kode.** [metrics:1282](../../apps/api/src/messaging-repository.ts#L1282) menghitung semua direction=outgoing; [overview:45](../../apps/web/src/app/overview/page.tsx#L45) melabelinya “Pesan terkirim”. Status unknown juga masuk pending tetapi dilabeli “Menunggu kirim”.

Snapshot read-only: outgoing=149, tetapi sent=129, failed=12, unknown=6, cancelled=2. Antrean otomatis pending=0; enam unknown memerlukan rekonsiliasi, bukan antrean pengiriman normal. Perbaiki filter/label dan tampilkan unknown sebagai prioritas rekonsiliasi. Tidak ada retry yang dilakukan pada enam pesan ini.

### QC-14 — Status AI di dashboard selalu “Belum dikonfigurasi”

**Dikonfirmasi live dan kode.** [operations.ts:119](../../apps/api/src/operations.ts#L119) mengembalikan not_configured secara konstan untuk chat/embedding. Database saat QC: integration active, generationEnabled=true, chat connection tersedia; dashboard tetap menyatakan belum dikonfigurasi.

Ambil status konfigurasi tenant sebenarnya; bedakan configured, unavailable, disabled, dan not_configured. Health configured tidak berarti provider sudah diuji respons live.

### QC-15 — Lint dan versi host menghalangi check/check:ci

Script impor memiliki console tanpa deklarasi global ESLint pada baris 578 dan 678. Node host 26.7.0 berbeda dari baseline 24.18.0. Detail dan perintah ada di laporan automated. Dua masalah berbeda; mengganti Node tidak memperbaiki lint.

### QC-16 — Baseline visual belum sesuai UI sekarang

10 tes visual gagal, sementara 8 tes aksesibilitas existing dan probe tambahan lulus. Inspeksi manual screenshot login menunjukkan baseline dark versus actual light; screenshot dashboard actual terbaca. Karena tes mengiterasi route lalu berhenti pada mismatch pertama, hasil ini **tidak** membuktikan seluruh screenshot halaman dalam setiap grup telah dibandingkan.

Tinjau perubahan desain dan data dinamis, kemudian perbarui baseline yang memang disetujui. Jangan otomatis menerima snapshot hanya untuk membuat gate hijau.

### QC-17 — Shared application image tidak konsisten antar-service

Read-only Docker inspect:

Container tetap berjalan; ini bukan bukti semua fitur service lama rusak (bahkan /agents sudah tersedia pada web live). Namun tes working tree tidak menjamin binary semua service live sama. Rencanakan deployment konsisten dan simpan image untuk rollback; restart/recreate tidak dilakukan selama audit ini.

## Reproduksi dan bukti

Dari root repository:

```sh
corepack pnpm exec playwright test --config playwright.config.ts --trace off
node docs/qc/browser-probe.mjs
apps/api/node_modules/.bin/tsx --tsconfig tsconfig.base.json docs/qc/whatsapp-security-repro.mts
apps/api/node_modules/.bin/tsx --tsconfig tsconfig.base.json docs/qc/rag-repro.mts
node docs/qc/qr-probe.mjs
```

- [whatsapp-security-repro](whatsapp-security-repro.mts): empat reproduksi memakai repository/provider palsu dan server localhost; tidak mengirim pesan WhatsApp.
- [rag-repro](rag-repro.mts): chunk/PDF/lokasi/embedding gagal dengan input dan provider fixture.
- [qr-probe](qr-probe.mjs): login QC, semua request sesi dicegat mock, waktu browser dimajukan.
- [browser-probe](browser-probe.mjs): GET endpoint dan halaman, login/logout QC; tidak mencetak credential atau isi percakapan.
- [playground-probe](playground-probe.mjs): **disiapkan tetapi BELUM dijalankan**, menunggu izin ekspor ke provider. Jika dijalankan, menambah trace/usage dan mungkin memakai provider berbayar; tidak membuat outbox.

Sandbox sempat memblokir localhost/IPC dan registry pada beberapa tes; rerun dengan izin berhasil. Probe API awal menggunakan Node APIRequestContext yang tidak mengirim Secure cookie pada HTTP localhost; probe diperbaiki memakai fetch di browser, lalu seluruh 23 endpoint lulus. Kegagalan harness awal bukan bug autentikasi aplikasi.

## Batasan dan efek samping QC

- Tidak ada pengiriman pesan live, reset/reconnect WhatsApp, perubahan safety, publish knowledge, update dependency, atau deployment.
- Tes browser membuat login session/audit normal. Probe tambahan yang selesai melakukan logout; suite existing membiarkan session kedaluwarsa secara normal.
- Build menghasilkan ulang artifact Prisma/Next. **apps/web/next-env.d.ts otomatis berubah sehingga diff empat baris yang sebelumnya ada hilang dan file kini sama dengan HEAD.** Isi sebelumnya tidak tersimpan, sehingga tidak ditebak/direkonstruksi. Perubahan pengguna pada source lain tetap dipertahankan.
- Browser scan hanya memakai superadmin dan state halaman yang terlihat, bukan semua modal/aksi/role. Test mock memberi bukti tambahan untuk auth/RBAC tetapi bukan sertifikasi penetrasi penuh.
- Load test, restore backup, restart Redis/worker, upload dokumen nyata, pemulihan MinIO, dan pengiriman end-to-end belum diuji di stack terisolasi. Script smoke existing mengubah konfigurasi/data atau merestart service, sehingga tidak dipakai pada sesi operasional ini.
- Dua pekerjaan eksternal masih blocked: scan Docker Scout dan output AI live. Automatic approval review meminta persetujuan eksplisit atas ekspor metadata/payload; tidak dilakukan jalan pintas.
- Medical knowledge factual accuracy tidak ditinjau oleh tenaga medis dalam QC software ini.
